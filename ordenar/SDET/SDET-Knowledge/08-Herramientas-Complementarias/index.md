# 🛠️ Herramientas Complementarias

En el ecosistema de un SDET, además de los frameworks de automatización y lenguajes de programación, existen herramientas esenciales que facilitan la depuración, la gestión de la calidad y la documentación del sistema. Estas herramientas permiten una integración profunda en el ciclo de vida del desarrollo y aseguran que la automatización aporte valor real y trazabilidad.

---

## 📂 Contenidos del Módulo

### 1. [Swagger / OpenAPI](swagger-OpenAPI.md)
Estándares para la documentación y validación de APIs RESTful. Fuente de verdad para pruebas de contrato y generación de clientes.

### 2. [Fiddler & Charles Proxy](fiddler-Charles-proxy.md)
Herramientas de inspección y manipulación de tráfico HTTP/HTTPS, vitales para la depuración de comunicaciones entre cliente y servidor.

### 3. [Jira y TestRail](Jira-TestRail.md)
Gestión de incidencias, historias de usuario y casos de prueba. Integración de la automatización con la gestión de proyectos y trazabilidad.

### 4. [Escritura Gherkin (BDD)](gherkin-escritura.md)
Lenguaje para describir el comportamiento del sistema de forma declarativa, facilitando la colaboración entre negocio y técnica.

---

## 🎯 Objetivos de Aprendizaje

- **Validar** contratos de API utilizando especificaciones OpenAPI.
- **Interceptar** y modificar tráfico de red para simular escenarios de error o latencia.
- **Sincronizar** los resultados de la automatización con herramientas de gestión de pruebas.
- **Redactar** escenarios de prueba claros, mantenibles y orientados a negocio utilizando Gherkin.

> [!TIP]
> El dominio de estas herramientas complementarias diferencia a un automatizador de un SDET integral, permitiendo diagnosticar problemas complejos y mejorar la comunicación con todo el equipo.
